Fish S2 Pro runtime research#

This port recovers the retained C39 / agent-10 research candidate. The historical results measure the original complete candidate. The new paired reduced-patch experiment below measures the retained quantizer and waveform transport changes together. Earlier complete-port measurements remain separately labeled.

Runtime changes#

  • Encode reference code indices without running the quantizer’s unused reconstruction path. Full quantizer forward remains available for training and calls with extra arguments.

  • Retain waveform tensors in typed transport and return packed waveform bytes instead of Python sample lists, including the shared no-chunks streaming fallback.

The shipped s2pro_tts.yaml uses S2ProPipelineConfig, whose preprocessing stage defaults to GPU 0 after #2798. No shipped Fish configuration selects CPU preprocessing. Explicitly setting that stage’s gpu to null remains supported with upstream’s unmodified encoder and thread policy.

Following review, this PR no longer changes CPU Snake activations, convolution padding, preprocessing thread budgets or the process allocator’s mmap threshold. Those changes and their dedicated tests were removed so their CPU-only costs and benefits can be reviewed independently. The quantizer equivalence and waveform transport regression tests remain.

The pre-split and historical measurements below predate this scope reduction. They describe the specified complete historical revisions, including changes removed during review, and are not a new measurement of the reduced patch. In particular, the default-GPU pair also included the former thread policy and zero-width padding shortcut; its speedup cannot be attributed solely to the retained quantizer and waveform changes.

Reduced-patch protocol#

The four cohorts ran sequentially on the same Radix H200 and task-local Python 3.12 environment: SGLang 0.5.21, PyTorch 2.13.0+cu130, Transformers 5.12.1 and task-local CUDA compiler 13.4.92. Server/client affinity was 16 distinct physical cores, CPU 0–15, on a shared host without exclusive CPU reservation. Weights and compiler caches were warm. This environment is separate from the October 14 container; old/new values are not pooled.

Both arms use shipped s2pro_tts.yaml and default GPU reference encoding, upstream full-fp32/TF32-disabled encoder policy and 6 GiB preprocessing reserve. Every server log confirms preprocessing on cuda:0, eight workers and one shared intra-op thread. OMP_NUM_THREADS and the startup-timeout override were unset; default CPU planning is identical in both arms.

The unchanged 94730a87 client and scorers use all 1,088 pinned SeedTTS EN samples in native order, concurrency 16, seed 42 and a 2,048-token cap. Each cohort starts a fresh server and excludes 16 warmup requests. The order is non-streaming base/head, then streaming base/head. ASR uses its default concurrency 32; SIM uses batch one and complete waveforms for all cohorts. All model, dataset and scorer revisions are those in the pinned input table below. The generation/scoring commands in Reproduction apply to these two source revisions with the task-local paths substituted.

The current Fish unit suite passed 144 tests, with three accelerator cases deselected and no skips. Audited numeric records, script and protocol are backed up with remote byte verification. That repository requires access; this table and the reproduction instructions are self-contained. Raw audio and dataset text are not included in the compact backup.

Paired pre-split port measurements (2026-10-14)#

Base is upstream 94730a87b2b3b2f8383274918c3c4ed041821ecb after #2798; measured head is merge 27bc65d424382d4b1e5405f89a1a57801e4c6ee1. Both revisions use the default GPU reference encoder, retaining upstream’s full-fp32/TF32-disabled policy, warmup, process isolation and 6 GiB reserve. The CPU activation/padding and allocator fast paths are inactive for this GPU preprocessing path. Both source trees were clean and ran sequentially on the same allocated NVIDIA H200 (143,771 MiB, driver 595.71.05), using the unchanged 94730a87 benchmark client and scorers for both revisions.

Server and client affinity was CPU 0–15: 16 physical cores on the GPU-local NUMA node. These CPUs were not exclusively reserved; no 128 GiB host-memory cap was imposed. OMP_NUM_THREADS was unset so each revision used its own native preprocessing policy within the same affinity mask. This measures the complete port, rather than isolating a particular optimization.

The image was docker.io/hongccc/sglang-omni@sha256:ebe4239e29a764ee3a2806385c061c5fd438a26f01458e503d3822dcba5790df, with SGLang upgraded to 0.5.21 as required by the checkout, Python 3.12, PyTorch 2.13.0+cu130 and Transformers 5.12.1. Weights were already downloaded.

Each cohort used all 1,088 SeedTTS EN requests in native order, concurrency 16, seed 42 and a 2,048-token cap. Each mode started a fresh server and excluded 16 warmup requests using the first reference. Normal caching and default engine settings were retained. These are single runs on the current port, separate from the historical three-seed results below.

The unchanged benchmark loader pins the dataset revision above. Set MODEL_PATH and ASR_PATH to the local snapshots of the listed revisions, MODEL_ID to the checkpoint ID, OUT to a separate directory per cohort, and PORT to an unused port. Use s2pro_tts.yaml as CONFIG. Run the server from the selected base/head checkout, with the following environment also applied to the clients:

export CUDA_VISIBLE_DEVICES=0
export HF_HOME=/work/hf-cache
export SEEDTTS_SIM_CACHE_DIR=/work/sim-cache
export SGLANG_OMNI_TORCH_COMPILE_DEFAULT=0
export SGLANG_OMNI_STRICT_PORT=1
unset OMP_NUM_THREADS
taskset -c 0-15 python -m sglang_omni.cli serve \
  --model-path "$MODEL_PATH" --host 127.0.0.1 --port "$PORT" \
  --config "examples/configs/$CONFIG"

From the base checkout in another shell, wait for /health, then use the same mode for both warmup and measurement (MODE=() for non-streaming, MODE=(--stream) for streaming; Bash array syntax):

MODE=()
COMMON=(--model "$MODEL_ID" --meta zhaochenyang20/seed-tts-eval-arrow
  --lang en --concurrency 16 --port "$PORT" --seed 42 --max-new-tokens 2048)
taskset -c 0-15 python -m benchmarks.eval.benchmark_tts_seedtts \
  "${COMMON[@]}" "${MODE[@]}" --generate-only --use-existing-server \
  --max-samples 1 --warmup 15 --output-dir "$OUT/excluded-warmup"
nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name,used_gpu_memory \
  --format=csv,nounits
taskset -c 0-15 python -m benchmarks.eval.benchmark_tts_seedtts \
  "${COMMON[@]}" "${MODE[@]}" --generate-only --use-existing-server \
  --max-samples 1088 --warmup 0 --fingerprint --output-dir "$OUT"

Stop the owned TTS server before scoring its saved WAVs. Run both scorers from the base checkout; ASR uses the default concurrency of 32. The runtime SIM override below leaves the repository and waveform lengths unchanged:

taskset -c 0-15 python -m benchmarks.eval.benchmark_tts_seedtts \
  "${COMMON[@]}" "${MODE[@]}" --transcribe-only --skip-gpu-cleanup \
  --asr-model-path "$ASR_PATH" --server-timeout 3600 --output-dir "$OUT"
taskset -c 0-15 python -c \
  "import runpy; import benchmarks.tasks.tts as t; t.SPEAKER_SIMILARITY_BATCH_SIZE = 1; runpy.run_module('benchmarks.eval.benchmark_tts_seedtts', run_name='__main__')" \
  "${COMMON[@]}" "${MODE[@]}" --similarity-only --device cuda:0 \
  --output-dir "$OUT"

Saved evidence per cohort includes command arguments, source identities, startup/memory snapshots, speed_results.json, generated.json, and per-sample wer_results.json and similarity_results.json. This fixed English workload on one H200 does not establish multilingual, low-concurrency or smaller-device behavior.

Historical experiment#

Developed with RSI-Harness under OpenRSI proposal #154.

Research run: 185b0e62f4b34e518f85f587fc17c67e. Evaluated source inventory SHA-256: a397ed0a8c12616d841cc0d809dacc67f1da34311d46bd41d0436e8d9408af4f.

The original complete candidate was evaluated on one NVIDIA H200 with 16 physical CPU cores on one NUMA node and 128 GiB host memory, using SGLang 0.5.20 and PyTorch 2.13.0+cu130. Initial runtime source: 1523543056bf334bc2f4d69db23aad0a002cedf2.

The workload was the full SeedTTS EN set (1,088 requests, dataset revision 27f4c1adee83b5b29b7c4b375f6b976324bda308), native order, concurrency 16, streaming and non-streaming, each with seeds 42/43/44. Six runs contain 6,528 scored requests plus 96 excluded TTS warmups. Engine admission/decode caps were 64/64 and the token cap was 2,048. Independent original-source Qwen3-ASR-1.7B scored the generated WAVs after diagnostic ASR.

All 27 prescribed performance/quality gates passed, with zero scored failures or skips. WER admission used a 2% absolute cap; other performance gates allowed 3% tolerance against the preceding accepted candidate. The gain reported here is against the initial pristine baseline. Values, including percentiles, are arithmetic means of three per-run summaries, not pooled percentiles. WER does not establish perceptual or speaker equivalence.

Evidence and limits#

Frozen accepted metrics, pristine baseline, complete Judge output, and research snapshot. The evidence repository requires access; the tables above are self-contained.

Later C45 work did not replace the scored C39 candidate. The CPU activation fast path is conditional; other architectures retain the normal padding path. The paired follow-up above uses the current port and a separate x86/H200 allocation; its CPU policy and runtime differ from the historical snapshot.

The port started from upstream fa4e6d1f1b4c962ecc223e1422f6e879f5ce1141 and now includes upstream 94730a87b2b3b2f8383274918c3c4ed041821ecb, preserving its GPU reference encoder and newer runtime changes. Current-port CPU tests and full pre-commit checks are reported in the PR. The paired H200 measurements above cover SeedTTS EN at C16; multilingual and low-concurrency behavior remains unqualified.
